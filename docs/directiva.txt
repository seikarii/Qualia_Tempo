DIRECTIVA REVISADA 07: `enforce-dependency-inversion`

  Objetivo: Forzar que los constructores de servicios solo acepten interfaces, nunca clases concretas.

  Guía Lógica para el Ingeniero:

   1. Punto de Entrada: Implementa un visitor del AST que se active para cada ClassDeclaration.
   2. Filtrado de Clases: Dentro del visitor, lo primero es comprobar si la clase tiene el decorador @injectable. Si no lo tiene, ignórala y sal. No nos importa lo que
      hagan las clases que no son servicios.
   3. Localización del Constructor: Si la clase es un servicio, busca en su cuerpo el método constructor. Si no tiene constructor, no hay nada que hacer. Sal.
   4. Análisis de Parámetros: Itera sobre los parámetros del constructor. Te interesan los nodos TSParameterProperty.
   5. Consulta al Type Checker: Para cada parámetro, debes usar los parserServices para obtener su tipo semántico, no solo el texto. Necesitas el objeto Type de
      TypeScript.
   6. Detección de la Violación: Una vez tienes el objeto Type, comprueba sus flags. Si el símbolo del tipo contiene el flag ts.SymbolFlags.Class, has encontrado una
      dependencia de una clase concreta. Esa es la violación.
   7. Reporte del Error: Al detectar la violación, invoca a context.report para lanzar un error de linting que rompa la build. El mensaje debe ser inequívoco: Error en 
      'MiServicio': el parámetro 'miLogger' no puede ser la clase 'LoggerConcreto'. Debe ser una interfaz.

  DIRECTIVA REVISADA 08: `no-service-locator`

  Objetivo: Prohibir las llamadas a container.get() en cualquier lugar que no sea el Composition Root o los tests.

  Guía Lógica para el Ingeniero:

   1. Punto de Entrada: Implementa un visitor del AST que se active para cada CallExpression.
   2. Identificación de la Llamada: Comprueba si la expresión de llamada corresponde a container.get. Analiza el callee para verificar que el objeto se llama container y
      la propiedad get.
   3. Contexto de la Llamada: Si es una llamada a container.get, obtén la ruta del archivo que se está analizando a través del context.
   4. Aplicación de Excepciones: Compara la ruta del archivo con la lista de excepciones permitidas:
       * ¿Es inversify.config.ts? Si es así, la llamada es válida. Sal.
       * ¿Termina en .test.ts? Si es así, la llamada es válida. Sal.
   5. Reporte del Error: Si el archivo no está en la lista de excepciones, has encontrado un anti-patrón. Lanza un error de linting fatal con context.report. Mensaje:
      Error: El uso de 'container.get()' está prohibido fuera de 'inversify.config.ts' y los tests.
