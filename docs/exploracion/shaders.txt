# 1) Resumen físico (lo más importante — con fuentes)

* Los electrones en un átomo no están “en pequeñas bolas” sino descritos por **órbitales** — funciones de onda que dan la probabilidad de presencia y distribuyen carga alrededor del núcleo. Esto explica por qué cada átomo tiene una nube electrónica que actúa como su campo electrostático. ([Wikipedia][1])
* Las **fuerzas electrostáticas (ley de Coulomb)** dominan a distancia entre cargas: atraen o repelen según signo y decrecen con (1/r^2); es la base de interacción entre núcleos y nubes electrónicas. (esto es la raíz del “campo” clásico entre partículas cargadas). ([hep.physics.illinois.edu][2])
* Además de Coulomb, interacciones efectivas entre átomos neutrales surgen de **fuerzas de dispersión / van der Waals** (atractivas a distancias medias) y **repulsión fuerte** a distancias muy cortas; modelos usados en simulación son el **Lennard–Jones** (12–6) para interacción genérica. ([Wikipedia][3])
* Para modelar enlaces químicos (enlace covalente) se usan potenciales que permiten una profundidad de pozo y rotura de enlace — un ejemplo común es el **potencial de Morse** (mejor que un oscilador armónico para describir la rotura del enlace). ([Wikipedia][4])
* El **principio de exclusión de Pauli** (cuántico) impide que fermiones idénticos ocupen el mismo estado — en la práctica molecular esto explica por qué las nubes electrónicas “se ordenan” y evitan colapsar; en simuladores clásicos suele aproximarse como una fuerte repulsión de corto alcance o mediante términos de intercambio effective. ([Wikipedia][5])

# 2) Principio de modelado para tu sistema de partículas

Objetivo: cada partícula tiene un campo/“zona” alrededor que:

* **atrae** selectivamente para formar enlaces (cuando corresponda),
* ofrece **repulsión** corta para que no se solapen (evitar ocupación),
* y permita interacciones no-bonding (vdW) para agregación/estabilización.

Estrategia práctica (clásica / eficiente en GPU):

1. **Campo electrostático (long range)**: potencial coulombiano con carga (q) por partícula y corte (cutoff) práctico.
2. **Repulsión de núcleo / exclusión (short range)**: término fuerte que crece rápido cuando (r\to 0) (por ejemplo (r^{-12}) o una exponencial) para impedir solapamiento.
3. **Atracción intermedia (van der Waals)**: modelo Lennard–Jones (o Mie/Buckingham) para capturar atracción/repulsión sutil.
4. **Enlaces explícitos (cuando quieras moléculas)**: términos de vínculo (bond) y ángulo para imponer distancia y dirección (por ejemplo, potencial de enlace armónico o Morse + potencial angular).
5. **Direccionalidad electrónica**: para enlaces covalentes que requieren orientación (p. ej. enlaces tetraédricos), añade **potenciales angulares** y/o dipolos orientacionales.
6. **Exclusión cuántica (Pauli)**: se aproxima con un término repulsivo adicional o con restricciones topológicas (no permitir más de N enlaces por átomo, o usar “ocupancy” por orbital).

# 3) Ecuaciones útiles (lista práctica)

**Coulomb (potencial y fuerza)**
[
V_C(r) = k_e \frac{q_1 q_2}{r},\qquad
\mathbf{F}_C = -\nabla V_C = k_e \frac{q_1 q_2}{r^2}\hat{r}
]

**Lennard–Jones 12–6 (pairwise, no directional)**
[
V_{LJ}(r) = 4\varepsilon\left[ \left(\frac{\sigma}{r}\right)^{12} - \left(\frac{\sigma}{r}\right)^6 \right]
]
Fuerza: ( \mathbf{F}*{LJ} = -\dfrac{dV*{LJ}}{dr}\hat r ). (útil para exclusión corta y atracción de van der Waals). ([Wikipedia][3])

**Morse (enlaces quím.)**
[
V_{Morse}(r) = D_e\left(1 - e^{-a(r-r_e)}\right)^2 - D_e
]
permite ruptura de enlace con energía de disociación (D_e). ([Wikipedia][4])

**Término de enlace armónico (simplificado)**
[
V_{bond}(r) = \tfrac12 k_b (r - r_0)^2
]

**Término angular (direccionalidad)**
[
V_{angle}(\theta) = \tfrac12 k_\theta (\theta - \theta_0)^2
]

# 4) Cómo “darle” a cada partícula un campo en la práctica (estructura de datos y algoritmos)

* **Atributos por partícula**: posición (\mathbf{x}), velocidad (\mathbf{v}), carga (q), tipo (H, O, C...), parámetros de potencial ((\varepsilon,\sigma) o (D_e,a,r_e)), número máximo de enlaces, orientación (si aplica).
* **Cutoff**: usar un radio de interacción (r_c) para limitar cómputo (p. ej. (2.5\sigma) para LJ); fuera de (r_c) la interacción se ignora o suaviza.
* **Vecinos**: usar *spatial hashing* / grillas / Verlet lists para buscar sólo vecinos dentro de (r_c) (crítico en GPU).
* **Combinación de potenciales**: la energía total entre dos partículas suele ser suma de términos relevantes: (V_{tot} = V_C + V_{LJ} + V_{bond,(si\ existe)} + \dots).
* **Prevención de “ocupación”**: el término repulsivo de LJ o una exponencial (A e^{-br}) asegura que dos partículas no ocupen exactamente el mismo lugar. Adicionalmente, si quieres un efecto estilo Pauli más fuerte, aumenta la pendiente repulsiva o impón una corrección posicional (resolver penetraciones mediante proyección).

# 5) Sugerencia de parámetros iniciales (heurísticos)

* Lennard–Jones: (\sigma) ≈ tamaño efectivo (p.ej. 0.3–0.4 nm para H/ligero), (\varepsilon) ajusta la fuerza de atracción (kJ/mol escala en MD). En simulaciones artísticas puedes normalizar a unidades de pantalla.
* Cutoff: 2.5–3.0·(\sigma) para LJ.
* Morse para enlaces: (D_e) = energía de enlace (ajustable), (r_e) distancia de enlace, (a) determina rigidez (más grande → enlace más rígido).

> Nota: si estás simulando visuales o “qualia”-like particles (archivo GLSL que subiste), puedes usar parámetros arbitrarios y normalizados para estabilidad y estética.

# 6) Ejemplo de GPU/GLSL-friendly implementación (pseudocódigo + fragment/compute shader ideas)

Concepto: en un *compute shader* o *transform feedback*, para cada partícula i:

* leer posición/atributos de textura/buffer,
* buscar vecinos dentro de (r_c),
* acumular fuerzas de Coulomb + LJ + bond,
* integrar (verlet / RK2).

Pseudocódigo (GPU-friendly):

```glsl
// asumimos buffers: pos[], vel[], type[], params[] (sigma, eps, charge, bond info)
const float ke = 8.9875517923e9; // o normaliza

for each particle i { // shader invocation por i
  vec3 xi = pos[i];
  vec3 Fi = vec3(0.0);
  for each neighbor j in neighborhood(xi, rcut) {
    vec3 xj = pos[j];
    vec3 rvec = xj - xi;
    float r = length(rvec) + 1e-8;
    vec3 rhat = rvec / r;

    // Coulomb (con cutoff y suavizado si se necesita)
    Fi += ke * (charge[i]*charge[j]) / (r*r) * rhat;

    // Lennard-Jones 12-6
    float sigma = mix_sigma(i,j); // mezcla por regla de Lorentz-Berthelot si hay tipos
    float eps   = mix_eps(i,j);
    float sr = sigma / r;
    float sr6 = pow(sr,6.0);
    float vl = 4.0*eps*(sr6*sr6 - sr6);
    float f_lj = - ( -48.0*eps*sr6*sr6/r + 24.0*eps*sr6/r ); // dV/dr simplificado
    Fi += f_lj * rhat;

    // Si existe bond(i,j) -> Morse u armónico
    if (isBonded(i,j)) {
      float De = bondParams.D;
      float a  = bondParams.a;
      float re = bondParams.re;
      float morse = 2.0*De*a*(1.0 - exp(-a*(r-re))) * exp(-a*(r-re)); // dV/dr
      Fi += -morse * rhat;
    }
  }

  // Integración (verlet simple)
  vel[i] += (Fi / mass[i]) * dt;
  pos[i] += vel[i] * dt;
}
```

Notas prácticas:

* **Suaviza la singularidad de Coulomb** usando un término `1/(r + r_eps)` o un *screening* si trabajas en unidades visuales.
* **Normaliza constantes** si usas unidades de pantalla para evitar overflow o jitter.
* En *WebGL fragment shaders* sin compute: se pueden hacer pases de textura (ping-pong) con reducción por tiles o hacer N^2 si N pequeño.

# 7) Cómo representar “ocupación” / evitar que otra partícula entre en el mismo orbital

Opciones:

1. **Fuerte repulsión de corto alcance**: ajustar la parte r^{-12} (o exponencial) con parámetros que hagan la energía prohibitiva si r < r_min.
2. **Número máximo de enlaces / ocupación de orbitales**: dar a cada partícula un contador de enlaces; si está lleno, rechazar nuevos enlaces.
3. **Campo de ocupación (SDF o máscara)**: rasterizar por partículas un campo escalar (signed distance / occupancy) y evitar mover partículas a posiciones cuyo occupancy > umbral.
4. **Proyección posicional**: tras integración, detectar penetraciones y desplazar partículas fuera por mínima corrección (positional solver), útil para estabilidad.

# 8) Limitaciones físicas (honestas)

* **No puedes reproducir exactamente efectos cuánticos** (superposición, entanglement, states discretos) con solo potenciales clásicos; el modelo es una **aproximación efectiva**. Para efectos cuánticos reales se requieren tratamientos como DFT o métodos de química cuántica (muy costosos). ([Wikipedia][1])
* Para visuales / interacciones “tipo molécula” los potenciales descritos (Coulomb + LJ + Morse + angulares) son el acercamiento estándar en dinámica molecular y fuerzas en simulación computacional. ([Wikipedia][3])

## 📐 Estructura de Shaders para un Motor Qualia Unificado

Tienes tres niveles de simulación que deben convivir:

1. **Partículas / LivingSymbols (Lagrangiano)**

   * Son entidades discretas (posición, velocidad, identidad, campo asociado).
   * Se integran con fuerzas (Coulomb, Lennard-Jones, Morse, etc.) y también **leen el estado del campo** en su posición.
   * Shader: *compute shader* o *transform feedback* dedicado a partículas.

2. **Campos Continuos (Euleriano: QualiaManifold tricapa)**

   * `PhiField` (materia), `LuminiferousField` (luz), `AcousticField` (vibraciones/sonido).
   * Son rejillas discretizadas (2D o 3D según el caso).
   * Cada capa resuelve su PDE en paralelo en GPU.
   * Shader: *compute shader volumétrico* (un despacho por voxel o celda).

3. **Acoplamiento y Visualización**

   * Las partículas excitan el campo (ondas piloto, vibraciones, emisiones).
   * El campo guía a las partículas (gradientes, retroalimentación).
   * Visualización:

     * *Fragment shader* para muestrear el `LuminiferousField` y renderizar luz/efectos.
     * *Vertex/geometry shader* para deformar geometrías con `AcousticField` o `PhiField`.
     * *Postprocess shader* para sinestesia (colorear por frecuencia, intensidad, interferencia).

---

## 🎛️ Tipos de Shaders que necesitas

1. **Compute Shader de Partículas**

   * Toma buffer de posiciones, velocidades, tipos.
   * Calcula fuerzas entre partículas (short-range) + gradiente del campo (long-range).
   * Integra movimiento.
   * *Inputs:* SSBO con partículas, texturas 3D con campos.
   * *Outputs:* posiciones y velocidades actualizadas.

2. **Compute Shader del Campo (QualiaManifold Solver)**

   * Una invocación por voxel de la rejilla.
   * Aplica stencil para resolver Laplaciano + términos de acoplamiento entre capas (`Phi`, `Luminiferous`, `Acoustic`).
   * Implementa ecuaciones acopladas definidas en [17].
   * *Inputs:* estados anteriores de las tres capas, excitaciones de partículas.
   * *Outputs:* nuevos estados de las capas.

3. **Shader de Visualización de Campos**

   * *Fragment shader volumétrico* para raymarching de `LuminiferousField` → luz emergente.
   * *Surface/heightfield shader* para mostrar vibraciones en 2D (`AcousticField`).
   * *Color mapping shader* para convertir frecuencias a color (timbre → espectro visible).

4. **Bridge Shader (Opcional / Híbrido)**

   * Si quieres FLIP-style coupling (partículas ↔ campo), un shader que interpole datos de campo a partículas y deposite partículas en el campo.
   * Usaría scatter/gather o texturas con blending.

---

## 🧩 Cómo se combinan en el pipeline

1. **Step 1 – Update Fields (Euleriano)**

   * Compute shader corre el update del `QualiaManifold` (3 capas).
   * Incorpora excitaciones de partículas (fuentes acústicas/lumínicas).

2. **Step 2 – Update Particles (Lagrangiano)**

   * Compute shader de partículas calcula fuerzas entre partículas **+ gradientes del campo** en su posición.
   * Se mueven.

3. **Step 3 – Rendering / Emergence**

   * Fragment shaders leen campos y partículas.
   * Luz se renderiza emergiendo del `LuminiferousField`.
   * Vibraciones afectan geometría/materiales vía `AcousticField`.
   * Partículas se dibujan como *billboards* o *instancias* pero moduladas por el campo.

4. **Step 4 – Postprocesado / Sinestesia**

   * Mapear música real a excitaciones en `AcousticField`.
   * Vibración → luz → materia (emergente).
   * Post-shaders para bloom, interferencia, espectros.

## 🔑 Características clave por shader

* **Compute (Partículas):**

  * Buffer-friendly (SSBOs / Shader Storage).
  * Neighbor search (hash grid o texel lookup).
  * Acceso al campo vía textura 3D.

* **Compute (Campos):**

  * Operaciones tipo Laplaciano (6 vecinos en 3D).
  * Ecuaciones acopladas:

    * `dPhi/dt += C1 * grad(Acoustic)`
    * `dLumin/dt += C2 * Acoustic.amplitude * f(freq)`
    * `Acoustic.speed = C3 * f(Phi, Lumin)`

* **Fragment (Visualización):**

  * Raymarch / sampling volumétrico.
  * Mapping frecuencia→color, amplitud→intensidad.
  * Posible FFT del sonido en GPU para excitar campos.

## 🚀 Recomendación práctica (mínima viable)

* 1 **Compute Shader** para campos (QualiaManifold tricapa).
* 1 **Compute Shader** para partículas (LivingSymbols).
* 1–2 **Fragment Shaders** para renderizar luz (volumétrico) y vibraciones (superficial).
* 1 **Postprocess Shader** para sinestesia y efectos globales.

En total: **4–5 shaders principales**, cada uno modular y conectado por SSBOs / texturas 3D.
